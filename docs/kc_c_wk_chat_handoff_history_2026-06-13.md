## 1. 项目总目标

用户希望在 GitHub repo `yt-feng/kc_c_wk` 中建设一个自动化系统，每周生成中文 Word 版《加密货币观察》周刊，并保存到 repo。

核心目标：

1. 每周三北京时间下午 4 点前生成一版《加密货币观察》。
2. 自动抓取英文加密货币相关新闻与研究报告，排除所有中文网站。
3. 参考用户提供的《加密货币观察》样刊和“编译模板”的版式、栏目结构、字体字号、目录页和正文页行距。
4. 文章必须基于真实原文链接直接编译，不能胡编、不能加入原文没有的观点或判断。
5. 生成主刊 Word 与独立专题研究 Word；专题研究英文原文 PDF 也必须保存到 repo。
6. 通过 GitHub Actions 定时运行并自动提交输出文件。

## 2. 主刊《加密货币观察》的目标结构

主刊固定栏目：

| 栏目 | 数量 | 要求 |
|---|---:|---|
| 政策风向 | 3 条 | 至少 1 条美国资讯；优先美国、香港，但 3 篇不要全是同一地区；优先已经确立的监管动向，如正式立法、规则、监管指南、牌照、法院/官方动作等。 |
| 行业前沿 | 2 条 | 区块链基础设施、协议升级、代币化结算、DeFi、RWA、跨链、预言机、钱包、安全、验证者、支付基础设施等技术或产品进展。 |
| 市场动态 | 2 条 | 用户后续要求市场动态的文章选取标准改成和行业前沿一样；实践中可覆盖融资、并购、IPO、交易产品、机构采用、稳定币供给、预测市场、交易所与市场基础设施，但避免纯价格预测。 |
| 意见领袖 | 2 条 | 必须体现人物或机构观点，正文可适当写“XXX认为”“XXX指出”“XXX表示”“XXX警告”，但观点主体和内容必须来自原文。 |

主刊不再内嵌【专题研究】正文。专题研究已被拆分为单独 Word 文档。

## 3. 主刊文章内容标准

用户多次强调，主刊文章不能是简析、摘要或模型扩写，必须是原文链接的中文编译。

当前标准：

1. 每篇文章需要完整编译原文主要事实，而不是短摘要。
2. 每篇文章开头放 1—3 条关键点，每条约 30—70 字，可灵活调整。
3. 正文应使用流畅、自然、专业的中文，全文基调一致。
4. 专业术语首次出现时采用“中文（English，缩写）”格式，例如“交易所交易基金（Exchange-Traded Fund，ETF）”。
5. 除特朗普等极高知名度人物外，英文人名不翻译；首次出现使用 `Firstname Lastname`，后文可用姓氏。
6. “今年”“本周五”“近日”等相对时间应改成具体日期；不能确定具体日期则删除相对表述。
7. 全文使用全角中文标点，尤其引号必须使用中文全角引号。
8. 标题需准确概括核心事实，不能采用两句式，不能用逗号硬拆。例如：
   - “美国参议员卢米斯推动CLARITY法案，寻求数字资产监管明确化”应改为“美国参议员卢米斯推动CLARITY法案明确数字资产监管”。
   - “韩国请愿达到5万签名，政府将重新审议加密货币征税计划”应改为“韩国政府将重新审议加密货币征税计划”。
9. 信息来源行格式为：`（信息来源：CoinDesk）`，删除发布时间，并右对齐。
10. 正文仍需输出“原文标题/原文链接”。
11. 信息来源必须是原始媒体或机构，不能写 Bing News、Google News、GDELT 这类发现渠道。
12. 所有链接必须是真实可打开的原文链接，不能是字体、CSS、Google 包装页、搜索结果页或无效链接。
13. 生成前后要做 fact check，防止链接错误、来源错误、重复文章、旧新闻、半角引号和编造内容。

## 4. 专题研究的目标结构

用户后续明确要求将专题研究从主刊中拆分出来，单独生成 Word：

1. 删除主刊中的【专题研究】板块。
2. 单独生成 `专题研究_YYYYMMDD.docx`，保存到原输出文件夹。
3. 选择近 2 个月内的一篇英文 PDF 研究报告进行翻译编译。
4. 不得把不同报告揉在一起。
5. 报告来源优先包括但不限于：PwC、KPMG、BCG、PitchBook、McKinsey、BIS、Deloitte、EY、Citi、JPMorgan、Coinbase Institutional Research、Chainalysis、Galaxy、CoinShares、TRM Labs、FATF、Messari、Glassnode、CoinDesk Data、The Block Research、a16z crypto 等。
6. 只要英文报告，不要中文报告。
7. 主题需与 crypto、digital assets、tokenization、stablecoin、blockchain、DeFi、Web3、RWA 等相关。
8. 原始英文 PDF 必须保存到 GitHub repo，建议路径：`reports/YYYY/research_sources/YYYYMMDD/<英文原文PDF>.pdf`。
9. 先下载 PDF，用 Python 提取文本，再用 DeepSeek 分块润色翻译。
10. 目标长度为 15—20 页，至少 24 段、约 12,000 中文字符。
11. 必须严格按照当前 Word 格式排版。
12. 如果找不到近 2 个月内发布的合格英文长篇 PDF，不能拿旧报告凑数。

专题研究历史问题：

- 曾错误选到 2024 年 10 月 IJBL 法律期刊 PDF，不符合“近 2 个月”。
- 曾错误选到 2024 年 1 月 Galaxy 报告。
- 曾错误选到旧 Galaxy Research PDF，例如标题或文件名中含 `September_18_2025`，应被识别为过期。
- 曾生成不到 15—20 页，只有几千字。
- 后续修复要求：只接受报告本身发布日期在近 2 个月内，不能用 PDF metadata、下载时间或正文中随便出现的近日期蒙混过关。

## 6. GitHub Actions 要求

用户要求最后给 GitHub Action 定期推送到 repo。

当前 workflow：`.github/workflows/weekly-crypto-observer.yml`

关键设定：

```yaml
schedule:
  - cron: "17 5 * * 3"
```

含义：每周三 UTC 05:17，约北京时间周三 13:17 运行，理论上能在北京时间下午 4 点前生成。

手动运行支持：

- `days`：新闻回溯天数，后来从 3 天改为 7 天。
- `strict`：`1` 表示 fact check errors 时失败，`0` 表示写草稿。

后续修复中还增加了专题研究与主刊解耦逻辑：

- 主刊通过 fact check 即可提交。
- 如果专题研究找不到近 2 个月合格英文 PDF，默认不拖垮主刊。
- 如需强制专题研究也成功，可通过 `CRYPTO_OBSERVER_RESEARCH_STRICT=1` 或命令行 `--research-strict`。

## 8. 历史迭代过程概览

### 8.1 初始实现

用户最初要求：

- 在 `kc_c_wk` repo 写代码。
- 每周生成《加密货币观察》周刊。
- 参考“加密货币观察AI模版”的栏目设置。
- 在“加密货币观察_网站”中搜寻相关资讯。
- 起初要求信息必须是最近 3 天事件。
- 生成：政策风向 3 条、行业前沿 2 条、市场动态 2 条、意见领袖 2 条、专题研究 1 篇。
- 政策风向必须至少 1 条美国资讯。
- 排除中文网站。
- 参考 `https://github.com/yt-feng/kc-m-a` 的 approach。
- 每周三北京时间下午 4 点前生成中文 Word。
- 输出前要 fact check，不要编造内容。

随后要求：

- “你直接全部实现，最后给个 github action 定期推到 repo”。

### 8.2 运行报错与 workflow 修复

多次 GitHub Actions 报错截图后，主要修复过：

- JSON DeepSeek 返回格式不稳定。
- workflow `strict` 输入传参问题。
- 文件未全部写入仓库。
- 自动提交 reports 目录的问题。
- run workflow 中 `Use workflow from`、`strict=0/1` 的行为。
- 提交生成报告和修复 commit。

### 8.3 Word 格式与样式修复

用户指出：

1. 没有参考“编译模板”的格式，字体字号不对。
2. 目录中缺少【政策风向】【行业前沿】等栏目标题。
3. 每篇文章需要全文编译，不是简析。
4. 信息来源行删除发布时间，只保留 `（信息来源：XXX）` 并右对齐。
5. 标题不要两句式，不要逗号式标题。
6. 正文段后、首行缩进 2 字符、行间距、对齐方式不对。
7. 目录页与正文页行间距不同。
8. 引号必须用全角。
9. 正文仍需输出“原文标题/原文链接”。
10. 正文依然太短，必须全文编译。

后续多次调整 `docx_writer.py`、标题清洗、标点清洗、fact check 和生成提示词。

### 8.4 新闻时效调整

用户先要求最近 3 天，后续明确修改：

- 新闻时间严格检查，不超过当前时间两周前。
- 后来重新要求：不超过当前时间一周前。

当前主刊默认按 7 天窗口。

### 8.5 市场动态选题标准调整

用户要求：

- 【市场动态】的文章选取标准改成和【行业前沿】一样。

后续配置中市场动态仍覆盖市场基础设施、机构采用、交易产品等，但应避免纯价格预测和无技术/产品/商业实质的文章。

### 8.6 专题研究拆分与修复

用户要求：

- 主刊中的专题研究删除。
- 专题研究独立成 Word，命名 `专题研究_YYYYMMDD`。
- 近 2 个月的一篇英文 PDF 研究报告翻译。
- 原文 PDF 保存到 repo。
- 15—20 页。
- 不拼接多篇报告。

修复过的问题：

- 旧 PDF 被误选。
- 不是近 2 个月。
- 文档过短。
- 没有保存英文原文 PDF。
- 把不同报告拼在一起。
- PDF metadata 时间误判为报告时间。
- 正文中随便出现的日期误判为报告发布日期。

当前逻辑：

- 要求报告标题、URL、搜索摘要或 PDF 封面/前几页出现近 2 个月的报告发布日期证据。
- 不接受 PDF metadata 日期。
- 不接受正文里无关日期。
- 如果找不到合格报告，默认不拖垮主刊，但会写失败 manifest。

### 8.7 真实链接和来源错误修复

用户指出：

1. 原文链接打不开，不是真实链接。
2. 信息来源错误，例如 `financefeeds.com` 的报道被写成 `Bing News`。
3. 曾出现字体/CSS/Angular license 被当作报道来源。

修复方向：

- Google/Bing/GDELT 只作为发现渠道。
- 解析真实最终 URL。
- 从 `og:site_name` 或域名识别媒体名。
- 屏蔽 `googleapis.com`、`gstatic.com`、字体文件、CSS、`angular.dev/license` 等。
- fact check 中禁止 `Bing News`、`Google News`、`GDELT` 作为最终信息来源。

### 8.8 重复内容和错误选题修复

用户指出：

- 生成报告中大量重复内容。
- 除某一篇【行业前沿】以太坊 Glamsterdam 升级文章外，其他完全错误。
- 该文章的信息来源也应为 FinanceFeeds，而不是 Bing News。

修复方向：

- URL、标题指纹、正文指纹三层去重。
- 每篇文章全局只能使用一次。
- 明确拒绝 license/CSS/font/Angular 页面。
- 如果栏目找不到合格文章，strict 模式失败，不再硬凑。

### 8.9 参考样刊后的重构

用户上传多份样刊，并表示“这才是我要的周刊效果”。样刊特点：

- 目录结构清晰。
- 每篇选题有真实新闻价值。
- 关键点与正文完整、专业。
- 信息来源真实。
- 专题研究是单一报告的系统编译。
- 正文不是短摘要，也不是无依据扩写。

重构方向：

- 重新定义栏目选题标准。
- 扩展高质量信息源。
- 主刊先程序过滤真实来源，再由 DeepSeek 按样刊标准选题。
- 编译提示词改成样刊风格。
- 原文抓取长度提高，候选上限提高。
- 更新 `ARCHITECTURE.md` 记录样刊标准。

### 8.10 来源外扩写与事实核验优化

用户要求检查每篇文章是否都是链接直接翻译，是否胡编。

人工抽查后发现：

- 主事实大多能对上原文。
- 但少数文章结尾加入了原文没有的“未决问题”“整体来看”“业内人士指出”“分析师认为”“可能引发管辖权重叠”“更严格合规要求”等扩写。

后续修复：

- `deepseek.py` 增加二次事实核验 pass。
- 编译后再次把中文稿和英文原文交给 DeepSeek，只允许删除/改写未支撑内容，不允许扩写。
- 程序级删除高风险句子。
- fact check 拦截明显来源外总结。
- 后来发现 fact check 对“分析师认为/业内人士指出”过严，可能导致周刊失败，遂把这类泛化归属从 hard error 改为 warning，但仍保留编译阶段的来源支撑过滤。

## 11. 当前已知风险与待办

### 11.1 主刊质量风险

1. DeepSeek 仍可能加入原文没有的总结性表述。
2. 二次核验和程序过滤已降低风险，但仍建议定期抽查原文链接。

4. 严格 fact check 过严时会导致本周生成失败；过松则可能放过扩写。
5. “分析师认为/业内人士指出”目前为 warning，人工复核时要重点看是否有原文主体。

### 11.2 专题研究风险

1. 近 2 个月内长篇英文 PDF 不一定每周都有。
2. 如果找不到合格 PDF，会只生成主刊，并写失败 manifest。
3. 如果用户强制专题研究每周必须有，需要扩展更多研究源或允许非 PDF 网页报告，但这与用户当前“英文 PDF 报告”要求不完全一致。
4. PDF 文本提取质量会影响翻译长度和准确度。

### 11.3 Word 格式风险

1. 样刊格式要求非常严格，尤其目录页和正文页行距不同。
2. 正文首行缩进、段后、行距、字体字号、标题颜色、信息来源右对齐都需持续用样刊对比。
3. 引号必须全角，生成后应校验。
